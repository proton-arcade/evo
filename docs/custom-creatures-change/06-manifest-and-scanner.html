Manifest and scanner

Static folder discovery without a build system.

Why a manifest exists

A browser can fetch a known static file but cannot list arbitrary files in a served directory. cc/index.json is the small bridge: it names the creature files that the screen should request.

tools/scan-cc.js

  • Reads the repository’s cc/ directory.
  • Keeps case-insensitive .json filenames except index.json.
  • Sorts names deterministically.
  • Writes a stable object with a format marker and files array.
  • With --check, compares expected and current content and exits non-zero instead of writing.
node tools/scan-cc.js          # regenerate cc/index.json
node tools/scan-cc.js --check  # CI / review verification

Current manifest

{
  "format": 1,
  "files": [
    "g8t7r.json"
  ]
}

The screen still treats manifest content as untrusted. Even a hand-edited entry must pass parseManifest before a URL is formed.

Bundled file

cc/g8t7r.json contains an 11-joint, 13-bone, 16-muscle design and five evolved action brains. The file supplies the feature’s current hero and all six current rows: All, plus one row for each objective.

Checks tied to it

  • tests/custom-creature-view-test.js independently lists cc/ and compares it with the manifest.
  • tests/custom-creature-library-test.js scans each creature file while explicitly excluding index.json.
  • The verification pass ran node tools/scan-cc.js --check and received cc/index.json is up to date (1 file).

Restyle impact

No manifest, scanner or creature data changed in the light rebuild. Discovery remains independent of presentation.
