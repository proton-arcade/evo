Library logic

Parsing, validation, grouping and safe copying.

Why the logic is separate

js/core/customLibrary.js has no DOM dependency. It converts untrusted manifest/file input into shelf entries, derives labels and rows, and performs the non-destructive copy operation. That makes the behavior directly testable in Node and keeps presentation changes from changing data rules.

Manifest boundaries

parseManifest accepts either { "files": [...] } or a bare array. It keeps unique, plain, non-hidden .json filenames and rejects paths, .., index.json, non-strings and unsupported extensions. A manifest therefore cannot direct fetches outside cc/.

Two levels of file validation

Errors reject a file

  • Invalid JSON or wrong top-level shape.
  • No joints or non-finite joint coordinates.
  • Duplicate joint, bone or muscle ids.
  • Bones with missing joints.
  • Muscles or decorations with missing bones.

Warnings keep the design

A brain is omitted when its chromosome is not numeric, its network settings are invalid or its weight count does not match the design. Other fitting brains and the creature remain usable.

This distinction avoids the builder’s otherwise quiet normalization from showing a creature different from the file while still salvaging a sound design when one optional brain is bad.

Derived shelf data

  • The name comes from trimmed file content, then the filename without .json, then “Unnamed”.
  • Joint, bone and muscle counts are computed once per entry.
  • Brains are normalized in canonical objective order and exposed as a lookup plus display list.
  • Text helpers build the hero summary and Explore chip labels, including generation and finite fitness.
  • buildRows always emits “All creatures”, then only action rows that contain at least one match.

Non-destructive copy semantics

copyToMyCreatures identifies an existing entry only when both its name and encoded design match. A same-named but geometrically different creature is separate. For an existing match, only action brains not already present are added; a brain trained further by the player is never overwritten.

first copy     → create one design + every fitting brain
second copy    → same id, no duplicate, no replacement
missing action → add only that action
same name,
different body → create a separate design

Restyle impact

The light rebuild does not modify this file. Parsing, validation, row grouping and copy semantics remain byte-for-byte the behavior delivered by the original feature.
