Documentation

README, cc guide and this HTML record.

User-facing documentation

The root README.md documents Custom Creatures in the same vocabulary as the UI: featured creature, action rows, Explore, Simulate, safe copying, Copy JSON, file drop/picker, manifest generation and bad-file handling. Mobile guidance calls out snap-scrolling posters and Add file.

Folder documentation

cc/README.md is the operational guide for maintainers and creature authors. It explains:

  • putting a file in cc/ and regenerating the manifest;
  • the no-tooling file-drop path and its session lifetime;
  • validation and non-destructive copying;
  • the additive design-plus-brains file format;
  • editor import/export compatibility;
  • training and assembling a file with the headless tools;
  • the bundled g8t7r design and its five training results.

Code-level documentation

  • js/core/customLibrary.jsStates the error/warning distinction, folder limitations and copy guarantees.
  • js/render/viewModel.jsExplains strict/safe models, framing regions and poster options.
  • js/ui/custom.jsDescribes the screen boundary and comments timing, drag/drop, clipboard and inert-background decisions.
  • tools/scan-cc.jsDocuments write and --check modes in usage output.

This change record

docs/custom-creatures-change/index.html is the entry point. Each numbered subject has its own HTML file, all using one local stylesheet and no scripts, web fonts or network assets. The report can be opened directly from disk.

The requested marker is present as the first and last visible element of every report page, including the index.

Runtime isolation

The report directory is not linked from index.html, is not loaded by the app and does not affect the dependency-free runtime. It is a review artifact only.
